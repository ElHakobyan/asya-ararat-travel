# Asya Ararat Travel

Сайт: https://elhakobyan.github.io/asya-ararat-travel/
Админ-панель отзывов: https://elhakobyan.github.io/asya-ararat-travel/admin.html (ссылка «Admin» есть и в подвале сайта)

Заявки с формы и кнопки связи ведут на номер +374 93 10 83 03 (WhatsApp, Viber, Telegram).

## Как работают оценки

Отзыв на сайте состоит только из оценки звёздами (от 1 до 5), без имени и текста.

1. Клиент нажимает «Rate us», выбирает звёзды и нажимает «Send rating».
2. Оценка сохраняется в базе со статусом «На проверке». На сайте её никто не видит.
3. Администратор входит в админ-панель и нажимает:
   - **Опубликовать**: оценка учитывается на сайте (или **Опубликовать все**, если новых оценок несколько);
   - **Скрыть**: оценка убирается с сайта, но остаётся в базе (можно вернуть);
   - **Удалить**: оценка удаляется навсегда.
4. На сайте в разделе «Reviews» показывается средняя оценка, количество оценок и полоски по каждой звезде.

Пока база не подключена (шаги ниже), раздел показывает приглашение оценить, а кнопка отправляет оценку
в WhatsApp, Viber или Telegram.

## Подключение базы данных (один раз, бесплатно, ~10 минут)

Используется Supabase (supabase.com). Нужен только ваш email.

1. Зарегистрируйтесь на supabase.com и создайте проект (**New project**). Запомните пароль базы, но он нигде больше не понадобится.
2. Откройте **SQL Editor → New query**, вставьте весь текст из файла `supabase-setup.sql` и нажмите **Run**.
3. Откройте **Authentication → Users → Add user → Create new user**. Введите email и пароль администратора и поставьте галочку «Auto Confirm User». Затем нажмите на созданного пользователя и скопируйте его **User UID**.
4. Снова откройте **SQL Editor** и выполните (подставьте свой UID):

   ```sql
   insert into public.admins (user_id) values ('ВАШ-USER-UID');
   ```

5. Откройте **Project Settings → API** и скопируйте **Project URL** и ключ **anon public** (или «Publishable key»).
   Впишите их в файл `config.js` (или пришлите их Claude, он впишет сам). Эти два значения публичные, их не нужно прятать.

Готово: после публикации сайта оценки будут сохраняться в базе, а вы сможете войти в `admin.html` с email и паролем из шага 3.

### Важно про безопасность

- В `config.js` можно хранить **только** Project URL и ключ **anon public**. Ключ **service_role** и пароли туда добавлять нельзя.
- Доступ защищён правилами базы данных (см. `supabase-setup.sql`): посетители могут только отправить оценку на проверку
  и увидеть общую статистику опубликованных; менять и удалять оценки может только пользователь из таблицы `admins`.
- Чтобы закрыть доступ бывшему администратору, удалите его строку из таблицы `admins` или самого пользователя в Authentication.
- Если начнут приходить фальшивые оценки, их можно удалять в админ-панели. При необходимости можно добавить капчу.

## Как устроен код сайта (для разработки)

`index.html` **собирается автоматически** из маленьких файлов в папке `src/`. Правьте только `src/`, а не `index.html`.

```
src/
  index.template.html     порядок блоков страницы
  partials/               header, hero, perks, tours, about, gallery, reviews,
                          contact, lightbox, review-dialog, whatsapp-float, footer, head
  css/                    01-base, 02-mockup, 03-polish (порядок важен)
  js/                     01-i18n (переводы), 02-reviews, 03-language-menu,
                          04-navigation, 05-lightbox, 06-reveal
```

**Что где менять**

| Нужно изменить | Файл |
|---|---|
| Меню, логотип, кнопка языка | `src/partials/header.html` |
| Блок туров | `src/partials/tours.html` |
| Контакты, форма | `src/partials/contact.html` |
| Подвал | `src/partials/footer.html` |
| Тексты на EN / HY / RU | `src/js/01-i18n.js` |
| Meta-теги, SEO | `src/partials/head.html` |

**Порядок работы**

```
node build.mjs         # собрать index.html из src/
node tests/check.mjs   # проверить, что ничего не сломано
```

Проверка смотрит: собран ли `index.html`, нет ли синтаксических ошибок в JS, существуют ли все `id`, на которые ссылается код, ведут ли ссылки `#...` на реальные секции, есть ли каждый текст на всех трёх языках и лежат ли на месте все картинки. Та же проверка запускается на GitHub при каждом push (вкладка Actions); красный крестик означает, что что-то сломано.

Сайт по-прежнему публикуется из ветки `main` как раньше: `index.html` лежит в репозитории в готовом виде.

## AI-помощник по продажам (чат на сайте)

Кнопка «Ask our travel assistant» открывает чат. Помощник отвечает на армянском, русском и английском, подбирает тур, задаёт уточняющие вопросы и, когда клиент серьёзный, просит контакт. Заявка попадает в админ-панель (вкладка **«Заявки клиентов»**: 🔥 горячие сверху) и приходит вам сообщением в Telegram. Решение о цене, брони и оплате всегда остаётся за вами: помощник ничего не продаёт сам.

**Как он защищён от ошибок.** Цены, даты и условия он берёт только из файла `supabase/functions/chat/tours.json`. Если там `null`, он честно говорит, что их уточнит менеджер, и ничего не выдумывает. Заявка сохраняется только если клиент оставил контакт. Просьбы вроде «забудь правила» игнорируются. Ограничения: не больше 40 сообщений в час с одного адреса и общий дневной лимит (по умолчанию 1500), чтобы не было неожиданных расходов.

Пока Supabase не подключён, кнопка чата скрыта и сайт работает как раньше.

### Что нужно подготовить (один раз)

1. **Supabase** (шаги выше, «Подключение базы данных»), если ещё не сделано.
2. В Supabase → SQL Editor выполнить файл **`supabase-agent.sql`** (таблицы заявок и лимитов).
3. **Ключ Anthropic API:** создать на console.anthropic.com (нужна оплата картой), в разделе Limits поставить **месячный лимит расходов**. Ключ нигде в код не вписывается.
4. **Telegram-бот для уведомлений** (по желанию): написать @BotFather, команда `/newbot`, сохранить токен; затем написать боту любое сообщение и узнать свой chat id (например, через @userinfobot).
5. В GitHub: репозиторий → Settings → Secrets and variables → Actions → **New repository secret** и добавить:
   `SUPABASE_ACCESS_TOKEN` (Supabase → Account → Access Tokens), `SUPABASE_PROJECT_REF` (часть адреса проекта до `.supabase.co`), `ANTHROPIC_API_KEY`, а по желанию `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `IP_SALT` (любая случайная строка).
6. GitHub → вкладка **Actions** → **Deploy AI agent** → **Run workflow**. Через минуту функция опубликована.
7. Вписать Project URL и anon key в `config.js` (как для отзывов): чат появится на сайте автоматически.

Секреты вы вводите только в окнах GitHub и Supabase; мне ключи присылать не нужно.

### Как обучить помощника

Откройте `supabase/functions/chat/tours.json` и впишите для каждого тура: количество дней, цену «от», ближайшие даты, что входит, размер группы, а также условия предоплаты, отмены и виз. Всё, что останется `null`, помощник не назовёт. После правки снова запустите **Deploy AI agent**.

### Проверки

`node --test tests/agent.test.mjs` проверяет логику агента, `node tests/chat-e2e.mjs` проходит весь сценарий в браузере (чат, заявка, смена языка, обрыв связи), `node tests/admin-e2e.mjs` проверяет вкладку заявок.

### Что стоит знать

- Армянские тексты чата написаны мной: пусть их прочитает носитель языка.
- Заявки содержат персональные данные клиентов. Видны только админу, удаляйте ненужные.
- Стоимость зависит от числа диалогов; следите за расходами в консоли Anthropic и держите лимит.

## Админка туров и цен

В `admin.html` добавлен раздел **Туры и цены**: RU/EN/HY, описание, даты,
программа, цена, валюта, обложка (ссылка или загрузка JPEG/PNG/WebP до 5 МБ),
порядок, черновик/опубликован/скрыт. Данные сохраняются в Supabase;
после обновления страницы сайт читает опубликованные туры без пересборки.
Перевод без названия использует русский, затем английский вариант.

### Однократное подключение

1. Выполните настройку Supabase и администратора выше (`supabase-setup.sql`).
2. Выполните **`supabase-cms.sql`** в SQL Editor. Он создаёт каталог, ограничения
   доступа и публичный бакет изображений. Существующие туры не перезаписываются.
3. Заполните `config.js`: Project URL и публичный anon/publishable key.
   Пароль администратора и service_role никогда не добавляйте в репозиторий.
4. После публикации файлов откройте `/admin.html` на адресе **нового** сайта.
   Войдите созданным email и паролем. Откройте «Туры и цены».
5. Измените один тур, сохраните как черновик: посетителям он не виден.
   Опубликуйте и обновите главную страницу: проверьте тексты, фото и языки.

Без подключения база не работает; HTML-панель сама по себе не создаёт аккаунт.
При ошибке сети сайт сохраняет исходные карточки. При доступной базе отображает
только опубликованный каталог. Если все туры скрыты, показывается приглашение
обратиться к менеджеру. Фото в бакете публичны; не загружайте документы клиентов.

**Ограничения:** этот раздел редактирует каталог туров. Тексты остальных разделов,
контакты и галерея пока остаются в `src/`. Каталог AI-помощника пока отдельный
(`supabase/functions/chat/tours.json`); изменение тура в админке не обновляет
ответы AI. Перед включением агента синхронизируйте его цены и условия.
